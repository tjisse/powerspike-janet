# Reproducible scenarios and calibration

The loadout tray keeps champion/level, core stats, six item slots and the current build cost together. The gold budget is configured in the Optimize build dialog. Opponent and fight controls, ability/rune/spell settings, saved scenarios and patch evidence live in expandable groups. Optimize build opens a modal with settings, progress and recommendations. Only Run search starts optimization; closing it leaves the search running, and reopening it shows the same job. Recommendations appear as up to ten rows ranked by the selected scoring preset, with metrics on each row and expanded loadout/coverage details. Their item icons reuse the loadout popover and do not edit the current inventory. Hover or focus champion, ability, item and rune icons for patch-specific details; select an item or champion to change it. Ability and rune details can be pinned with a click and dismissed with Escape.

Hover or focus an attack in the event list to highlight the same event on the damage, health and resource graphs. Click or press Enter to pin it. Highlighted state changes come from that exact trace event, including separate hits at the same timestamp. Outcome totals are trial means; graphs show the first seeded trial. Coverage and source records remain accessible under Patch & evidence.

Supported tooltip placeholders appear as colored calculated values. Hover or focus a value to inspect its formula, including the selected rank, level and stat contributions; click to keep the explanation open. Values use the displayed build at the start of the fight, and damage is before mitigation. Equipped items and recommendation rows use their own build stats. Item-picker values use the current participant's build and exact scenario snapshot. Unknown formulas and unavailable inputs retain their original placeholders. Resolving a tooltip number does not establish that its combat trigger is implemented or validated.

Each champion has a populated skill order under Strategies, ranks & activation rules. Edit the comma-separated Q/W/E/R sequence to choose one skill point per level. Changing champion level applies that sequence up to the selected level. Ability tiles keep their size, with the letter in the bottom-left corner and filled circles below the icon for learned ranks; unlearned icons appear dimmed. Ability priority controls casting order independently. Manual rank settings override the learned ranks. Skill orders survive saves, imports, sharing and optimization; imported scenarios must include a skill order for each champion, with enough entries to cover their level. Exceptional champion leveling rules remain outside the current standard rank validation.

Use a combat preset, configure both participants and their strategies, then choose a trial count and seed. Optimization evaluates this fixed scenario; it does not search the opponent or player decisions. Scores display their comparison order. Burst uses the configured window; sustained damage divides modeled damage by that window. Duel prioritizes win/kill probability and successful kill times. Survival prioritizes survival and health. Utility compares effective control, healing and absorption in order. Objective scoring uses objective kills, kill times and damage. Each chart has its own units and scale.

The shop search uses fetched map, champion, group and availability restrictions. Locks preserve owned items; other items can be replaced. In next-purchase mode the budget means gold available now, and each owned recipe component is credited once. Next-purchase mode keeps rune/summoner/skill choices fixed. The bundled excerpt searches only curated purchase rules; refresh the patch for complete sources. Full-shop searches screen individual items, seed complete budget-fitting inventories across stat families, then improve several leaders using deterministic mutations and crossovers. Inventory permutations are evaluated once, current legal inventories are retained as a comparison, and finalists use a common larger trial schedule. Small pools still use exact enumeration. Full-shop and optional loadout searches report best found. Source-defined purchase unlocks are excluded unless already owned; trinkets use a separate slot and are excluded from six-item searches. Parsed zero-cooldown abilities require charge/recast or champion activation handlers; otherwise they are excluded and reported instead of repeatedly casting and suppressing attacks. Rune choices cover primary/secondary effects; stat shards and exceptional leveling require further handlers and remain outside these estimates.

The gold limit is a spending ceiling. Recommendations are scored by the simulated stats and implemented effects, without a bonus for completing items or spending the entire budget. The result summary retains the limit used for that search. Missing passive effects can distort component-versus-upgrade comparisons; supported upgrades use the selected patch's numerical formulas and cooldowns, with remaining omissions listed in coverage.

The browser's practice target starts at 2,500 HP, 80 armor and 80 magic resistance. Target health remains editable and is retained in saved scenarios. Burst scores all damage, including abilities, attacks and item effects, over the configured combat window. A high-health target can favor percentage-health on-hit builds even for a mage. The optimizer shows the active target settings before a search and explores stat multipliers together with penetration to find combinations that standalone item scores can miss. Champion roles do not restrict items or add scoring bonuses.

Current combat semantics apply to the source records in cached snapshots too, without rewriting their files. The model identity records those semantics. Supported mage effects include Viktor's empowered Q attack and periodic R damage, and Ahri's three Spirit Rush casts; evolution, dash geometry, storm movement, pets and takedown resets still require further handlers.

Empowered attacks share a handler for additional damage, replacement damage, a fixed number of attacks and timed attack buffs. Bonus damage preserves the ordinary physical attack and resolves separately with its own damage type; total attack damage replaces the ordinary hit. Source spell tags identify attack resets. Empowerments refresh on recast and can coexist with bonuses from other abilities. The graph labels bonus damage with its ability and ordinary damage as an attack. Source-defined empowerment windows take precedence over unrelated slow or stun durations. If a finite attack count has no available expiry, the simulator reports that it assumes the empowerment lasts until those attacks consume it. Timed buffs without a known duration and passive or conditional triggers remain unresolved. The retained nine-champion regression fixtures check formulas and shared behavior, not in-game timing accuracy.

Completed combat evaluations are reused across search jobs in a bounded process cache (2,048 entries and 8 MB of encoded payload). Keys include the full scenario, exact patch/snapshot, model identity and trial count. Changing constraints or scoring reuses compatible combat metrics while checking legality and scores again. Partial/cancelled trials and custom evaluators are excluded. The modal reports reused results and new simulations; the selected compute budget still governs exploration. Cancellation uses independent in-memory channels. Search evaluates the shared engine without graph traces or actor-identity serialization; applying a build generates its full trace. The cache resets on restart. See [performance verification](optimizer-performance.md).

Save locally stores up to fifty named scenarios in the current browser (2 MB allowance). Export JSON creates a versioned document; import accepts at most 64 KB. Share links embed the same document, with a 16 KB URL allowance. Links carry game settings, not server-side saved records. Keep exact data snapshots cached for offline reproduction. Imports require their exact snapshot; an absent revision is an error, never a substitution. A different combat model displays a warning and recomputes against the retained data; use the original RPM to reproduce that older model.

The source evidence view displays exact provider versions, source URLs and hashes, snapshot identity and parser/model identities. Source availability, implemented effects and in-game measurements remain separate. The five retained Annie captures check their original stat conditions; they do not verify every combat handler.

## Packaged command line

The RPM includes these JSON commands; no separate interpreter is needed:

```sh
powerspike --simulate scenario.json --data-dir /var/lib/powerspike
powerspike --optimize search.json --data-dir /var/lib/powerspike
powerspike --calibrate measurement.json --data-dir /var/lib/powerspike
```

A search document has format `powerspike-optimization`, version `1`, a `scenario-document` containing an exported scenario, and `constraints` using the UI's field names (for example `searchbudget`, `searchslots`, `searchseconds`, `searchpreset`, `searchpool`, `searchexclude` and `lockslot1`). Item lists accept names or IDs. Output is JSON from the shared Janet engine. Existing development CLI entry points remain compatible.

## Calibration by mechanic family

Copy `observations/templates/calibration.json`, attach an exported scenario under `scenario-document`, and collect a measurement under exactly those fight conditions. Record the game version, source and capture time, measured metric/value, tolerance and required effect source. Set `reviewed` only after checking loadouts, buffs, target stats, timing and exclusions. Do not infer an absent measurement as zero or tune expected values to match the implementation.

Families are `isolated-damage`, `mitigation`, `timing`, `on-hit`, `healing-shields`, `control`, `objectives` and `combinations`. Use isolated damage first, then mitigation and timing; apply the same procedure to shared triggers, protection/control and objective restrictions before testing combinations. A missing observation is `unmeasured`. A missing required effect/metric is `unresolved`. Reviewed numerical comparisons are `consistent` or `mismatch`, and retain source/model identity and unsupported-effect notes. These statuses validate only the recorded conditions.

The five existing Annie stat captures remain unchanged and are still checked by the core regression suite. No additional in-game measurements have been invented during implementation.
