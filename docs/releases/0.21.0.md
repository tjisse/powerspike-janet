# PowerSpike 0.21.0

Champion and item catalogs now load when their picker opens, reducing the work
and HTML needed to show a fight. Search, snapshot-specific artwork, item details,
both champion sides and native forms remain available. Failed catalog requests
offer a retry; late responses cannot replace choices from a newer snapshot.

The catalog change reduced initial HTML from about 3.39 MB to 0.65 MB in a
controlled local executable comparison. Median warm first-byte time fell from
2.27 seconds to 0.77 seconds, with identical simulation results in all eight
runs. These measurements precede the small report form addition and describe
local performance. Public performance needs checking after deployment.

**Report a problem** now downloads a completed simulation with the player's
description, exact fight settings, pinned items and recorded outcomes. Nothing
is submitted automatically. The existing scenario importer can load the report
and reproduce both builds, including when switching between practice and duel
layouts. Edited, failed or incomplete simulations must be rerun before reporting
a completed result. Report descriptions survive closing the dialog during the
current page session.

Developers also have an opt-in hosted smoke check for simulation isolation,
finite SSE responses, search cancellation, save/load, swapping and desktop/touch
flows. Its target is supplied at runtime; there is no default production target.

Upgrade with:

```sh
sudo dnf upgrade --refresh powerspike
```

The package upgrade preserves administrator configuration and retained patch
data. Results remain simulations. Combat formulas, model identity and existing
scenario/comparison formats are unchanged; no new in-game combat measurements
are added. Reports use a separate versioned envelope around the existing saved
workspace document.
