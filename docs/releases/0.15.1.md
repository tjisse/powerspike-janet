# PowerSpike 0.15.1

The player interface presents a **simulated fight** with its configured conditions.
Verification progress, source hashes, calibration records and implementation
diagnostics move to `/developer`; the detailed verification dashboard remains at
`/verification`. Actual omitted mechanics and inventory rules remain available
in Simulation details. The champion and item pickers no longer display blanket
verification labels.

Practice and objective simulations can pin the current items and compare them
with an edited or optimized inventory. Damage, DPS and gold differences use the
same current champion, level, opponent, runes, skills, fight settings and trial
seeds. References from another champion or exact patch snapshot show an
explanation without replacing the current result. Pinned comparisons remain in
the open page session; saved and shared scenarios retain the selected build.

Failed scenario evaluations prevent saving, exporting or sharing the previous
result until a successful evaluation replaces it. The Goal control opens the
optimization settings. The paired champion matchup interface, independent
inventories, explicit runs, optimizer apply/undo and responsive controls from
v0.14.0 are preserved.

This release also includes the indexed replay evidence store and reviewed damage
comparison workflow added after v0.14.0. The bundled developer report contains
four admitted and evaluated cases across two of the 27 planned combat conditions.
Those cases agree within their declared numerical tolerance; they do not imply
whole-game accuracy. Developer workflows and scope are documented in
[replay evidence storage](../replay-evidence-store.md) and
[batch comparisons](../replay-batch-comparison.md).

Developer routes organize the interface; they do not add authentication.

Local formatting, core and Python suites, frontend and paired-matchup model
checks, relocated runtime, RPM payload checks and packaged Chromium tests passed.
The browser release gate now exercises both the practice comparison interface
and the paired matchup interface, including opponent optimization, apply/undo,
mobile layouts and the no-JavaScript form.

A clean build now prepares the native production-model dependencies before the
Python replay comparison tests. The v0.15.0 publication stopped at that test gate
and created no release assets; its tag is retained unchanged.

The [GitHub packaging and browser workflow](https://github.com/tjisse/powerspike-janet/actions/runs/39252024638)
and [signed RPM/DNF publication and installation workflow](https://github.com/tjisse/powerspike-janet/actions/runs/39252025986)
passed. Installation checks include a real upgrade, configuration/cache
preservation, reinstall and removal. The downloaded release RPM matches its
published SHA-256 and verifies against the dedicated PowerSpike signing key.
