# PowerSpike 0.19.0

Build comparisons now resolve all five special melee/ranged identities on the
retained 16.19.1 patch, using a selected fixed level or form:

- **Kayle:** level-dependent attack type and range.
- **Nidalee:** fixed Human/Cougar attacks and supported item scaling.
- **Jayce:** fixed Hammer/Cannon attacks, including Hammer's level/bonus-AD defenses.
- **Elise:** fixed Human/Spider attacks, movement speed and Spider Queen's magic damage/self-healing against champions and practice targets.
- **Gnar:** fixed Mini/Mega attacks, level-scaled range, movement, attack speed and base stats. Spellblade uses Mega's increased base AD.

Both participants choose independently. Item tooltips, comparisons and item
optimization use the same compiled form/level. Exports and share links preserve
those choices, and completed charts identify the selected forms. For transforming
champions, older scenarios without a selected form retain their previous
unknown-type exclusions. Existing cached snapshot bytes remain unchanged.

Ahri's ordinary windup now uses the reviewed 20% fraction. Annie's ordinary
projectiles travel at 1,500 units/second, and Viktor's at 2,300. Viktor's empowered
Q retains its separately stated zero-travel assumption.

Fiora W now provides its 0.75-second champion-only defensive window from cast
start, with movement and actions locked during the parry. Parried attacks consume
primed Spellblade while blocking its damage. The fight timeline exposes parry
activation, blocked effects and Spellblade consumption; crowded events remain
selectable on mobile.

These results remain simulations. Fixed forms persist throughout the run;
automatic transformations and unsupported casts/passives remain explicit
omissions. Gnar's Rage and Hyper, Kayle's remaining passive effects, Nidalee's
abilities, Jayce's transformation attacks and Elise's Spiderlings are excluded.
Riposte's return stab, shield ordering and exceptional interactions remain
outside its handler. Remaining timing assumptions appear in Simulation details.
The source-backed corrections and regression checks do not add newly admitted
in-game combat measurements.

Developer scope, sources and discrepancy decisions are documented in the
[improvement queue](https://github.com/tjisse/powerspike-janet/blob/v0.19.0/docs/next-improvements.md)
and its linked implementation notes.

Local formatting, core/source checks, all 170 Python tests (162 passed, eight
optional skips), frontend/combat regressions, standalone runtime, RPM payload
verification and desktop/mobile browser checks passed. Browser coverage includes
both participants, item optimization, saved/shared reproduction, native forms
and the sourced Riposte timeline.

The [clean packaging and browser workflow](https://github.com/tjisse/powerspike-janet/actions/runs/39377527330)
and [signed publication and DNF installation workflow](https://github.com/tjisse/powerspike-janet/actions/runs/39377527192)
passed. The downloaded RPM matches its published SHA-256 and verifies against
the dedicated PowerSpike signing key. DNF checks cover installation, a real
version upgrade, configuration/cache preservation, reinstall and removal.
